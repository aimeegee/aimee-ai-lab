# 照片清理工具 — 需求

## 目标

Aimee 每年把 iPhone 照片拷到电脑、再传 OneDrive 备份。原始照片里混着误拍的短视频、重复图片、临时截图等垃圾，占空间也不好翻。本项目做一个**本地运行的清理脚本**，在上传前把垃圾找出来：确定是垃圾的自动清掉，拿不准的集中放到一处，让 Aimee 扫一眼缩略图后自己决定。

成功的标准：
- 几千张照片的一批，跑一次就能分出各类垃圾，Aimee 只需要看「待复查」文件夹和报告，不用逐张翻原目录
- 不误删有价值的照片：除字节完全相同的副本外，脚本不删任何文件
- 全程本地计算，不调用 LLM / 视觉模型，几乎不耗 token

## 用户与场景

- 用户：Aimee 本人。她不想自己记命令行参数或翻使用文档——她习惯的交互方式是直接跟一个 Claude 会话说"清理这个文件夹的照片"并给出目录路径，由 agent 去调用脚本、读结果、把要点讲给她听
- 场景：每年一次（或不定期），把 iPhone 照片拷到电脑某个目录后、上传 OneDrive 之前：
  1. Aimee 在聊天里给 agent 一个目录路径，说"清理这个文件夹"；agent 据此找到脚本，先用预览模式跑一遍，把报告里各类垃圾的数量和有没有明显误判讲给她
  2. Aimee 确认后，agent 用执行模式跑：完全重复的副本被清掉，可疑项被移到「待复查」文件夹
  3. Aimee 在访达/资源管理器里按缩略图浏览「待复查」，确认是垃圾就手动删，判错的放回去（或让 agent 用还原功能）
  4. 按报告里的「截图」清单，自己挑出广告类截图删掉；收据、票据等留着
  5. 上传清理后的照片目录

## 范围

**做**
- 一个本地脚本，输入是一个照片目录（含子目录），处理其中的图片和视频
- **判断方法只用本地算法，不用 LLM / 视觉模型逐张看图**（几千张会很慢、很费 token）。已认可的方法论：
  - 完全重复：按文件内容的字节级哈希比对
  - 重复 / 相似图片：感知哈希（perceptual hash）聚类，同一组里保留一张。保留规则按优先级：① 组内有文件名配对的编辑/裁剪版（如 `IMG_1234` 与 `IMG_E1234`）→ 保留编辑版；② 组内有非截图版本（按截图识别规则判断）→ 保留非截图版本；③ 否则保留像素数最多的一张，像素相同保留文件更大的
  - 「截图前 / 截图」成对的两种情况都要覆盖（Aimee 确认都有）：(a) 原图与编辑 / 裁剪版成对；(b) 对自己拍的照片又截了屏——截屏画面包含原照片内容（可能带状态栏等系统 UI），只要感知哈希能把截屏和原照片的主体内容匹配上，两者归入同一相似组，按上面的保留规则留下原照片
  - 误拍短视频：读取视频元数据里的时长，低于阈值即标记
  - 截图识别：iPhone 截图的分辨率等于设备屏幕像素，且没有相机 EXIF（无 Make / Model / GPS），以此和相机照片区分
- **安全原则**（Aimee 已认可）：
  - 只自动删除「确定性高」的垃圾：字节完全相同的副本，每组保留一个。删除方式为移到系统废纸篓 / 回收站，不做永久删除
  - 相似图组里的多余项、短视频：移到「待复查」文件夹，脚本不删除
  - 截图只做识别和分类（列入报告的截图清单），不移动也不删除；除非它同时命中完全重复或相似规则，这时按那条规则处理。原因：截图里可能有收据、票据等重要信息，脚本无法判断是不是广告
- Live Photo 支持：与图片同名的 .MOV 伴生文件和图片视为一个整体，不单独当短视频处理；图片被删除或移动时，伴生文件一起处理
- 预览模式：只生成报告，不动任何文件
- 执行模式：按上述规则删除 / 移动，并生成报告和操作记录
- 「待复查」文件夹放在输入目录之外（避免上传时被一起传上去），按类别分子文件夹，相似组按组再分子文件夹
- 报告：列出每个被命中文件的类别、命中原因、动作，以及每组保留了哪个文件；附各类数量汇总
- 还原：按操作记录把「待复查」里的文件放回原路径
- 验收样本集：Engineer 准备一组带标注的样本（可合成，最好混入 Aimee 提供的真实样本），各条 AC 在这组样本上判定
- 清楚到 agent 不用问人就能读懂并正确调用的接口（命令行参数说明，或封装成一个 Claude Code skill）：agent 只凭 Aimee 给的目录路径和"清理这个文件夹"这句话，就能找到脚本、默认先以预览模式运行、把报告摘要转述给 Aimee

**不做**
- 不用 LLM、视觉模型或任何云服务判断图片内容
- 不识别截图内容（不做 OCR，不判断是广告还是收据），截图的去留由 Aimee 自己决定
- 不自动删除字节完全相同副本以外的任何文件
- 不处理模糊、过曝、闭眼等照片质量问题
- 不改动保留下来的照片本身：不转格式、不改 EXIF、不重命名
- 不负责从 iPhone 导出照片，也不负责上传 OneDrive
- 不做图形界面、安装包；不要求 Aimee 自己记命令或读使用文档——她只需要在聊天里把目录路径给 agent
- 不和 OneDrive 上已有的照片或往年批次做跨批次去重（以后需要再单独提）

## 验收标准

样本集的最低组成见各条 AC；「原目录」指输入的照片目录。

**通用 / 识别（预览模式即可判定）**

- AC-1: 断开网络后，脚本能对样本集完整跑完预览和执行两种模式；运行期间没有任何对外网络请求
- AC-2: 报告对每个被命中的文件给出：原路径、类别（完全重复 / 相似 / 短视频 / 截图）、命中原因（例如所属组号、视频时长秒数）、动作（删除 / 移至待复查 / 仅标记），对完全重复和相似组标出该组保留的文件；报告末尾有各类别的文件数汇总，汇总数与明细行数一致
- AC-3: 预览模式运行前后，原目录中所有文件的路径、大小、内容哈希、修改时间完全一致，且没有创建「待复查」文件夹
- AC-4: 样本集含至少 10 组字节完全相同、文件名不同的文件（如 `IMG_0001.HEIC` 与 `IMG_0001 (1).HEIC`），全部被识别为完全重复，每组恰好标出 1 个保留文件；文件名中不带「 (1)」「-1」这类副本后缀的优先保留，都带或都不带时取文件名排序第一个。另有 1 对内容只差 1 字节的文件，不被判为完全重复
- AC-5: 样本集含至少 20 组已知相似图片（同一张照片的缩放、重新压缩、HEIC 与 JPG 两种格式版本），其中至少 5 组是 (a) 原图 + 文件名配对的编辑/裁剪版（如 `IMG_1234` / `IMG_E1234`），至少 5 组是 (b) 原始照片 + 对该照片的截屏；每组的所有成员都被归入同一个相似组，20 组全部识别
- AC-6: 样本集含至少 50 张场景互不相同的照片，其中被误归入任何相似组的为 0 张
- AC-7: 每个相似组标出的保留文件按「做」中的保留规则选取：有文件名配对的编辑版就留编辑版（对应 AC-5 的 (a) 组）；没有编辑版但组内有非截图版本就留非截图版本（对应 AC-5 的 (b) 组）；否则留像素数最多的一张，像素相同时留文件更大的
- AC-8: 视频时长低于阈值（默认 3 秒，可通过参数修改）的被标记为短视频。用时长约 1 秒、2.9 秒、3.0 秒、10 秒的视频测试：前两个被标记，后两个不被标记
- AC-9: 样本集含至少 10 组 Live Photo（图片 + 同名 .MOV，.MOV 时长低于短视频阈值），这些 .MOV 无一被标记为短视频
- AC-10: 样本集含至少 20 张 iPhone 截图（覆盖至少 3 种屏幕分辨率）和至少 30 张相机照片（含竖拍、横拍、裁剪过的），截图至少 19 张被识别为截图，相机照片被误识别为截图的为 0 张
- AC-11: 每个文件在报告中只对应一个动作，规则冲突时按优先级取：完全重复 > 相似 > 短视频 > 截图标记。用一张同时是截图且有完全相同副本的文件测试，报告中它只出现一次，类别为完全重复
- AC-12: 对 5,000 个文件（照片与视频混合）的目录，在 Aimee 的电脑上预览模式 30 分钟内跑完

**执行模式**

- AC-13: 执行后，AC-4 中每组完全重复只剩保留文件在原位，其余副本（及其 Live Photo 伴生文件）出现在系统废纸篓 / 回收站中
- AC-14: 执行后，每个相似组的保留文件仍在原位；其余成员被移到「待复查/相似/<组号>/」下，组文件夹名或报告能对应到该组的保留文件；「待复查」文件夹位于原目录之外
- AC-15: 执行后，AC-8 中被标记的短视频被移到「待复查/短视频/」；相似组多余项若有 Live Photo 伴生 .MOV，伴生文件和图片移到同一个文件夹；执行后原目录和「待复查」中都没有失去对应图片的孤立伴生 .MOV（样本集里本来就单独存在的除外）
- AC-16: 执行后，只被识别为截图、没有命中其他规则的文件全部仍在原位，内容和修改时间不变
- AC-17: 执行前后文件数满足：（原目录文件数 + 「待复查」文件数）= 执行前原目录文件数 − 被删除的完全重复副本数；被删除的文件全部能在报告的「完全重复」类别里找到
- AC-18: 每次执行生成一份操作记录，含每个被删除 / 移动文件的原路径和去向；运行还原后，「待复查」里的文件全部回到原路径，原目录与执行前相比只差被删除的完全重复副本
- AC-19: 对同一目录在执行后再跑一次执行模式，不产生新的删除或移动；目录中的非图片 / 非视频文件（如 .txt、.AAE）不被删除或移动

**每年复用**

- AC-20: 换一个新目录（例如另一年份的照片），只通过命令参数指定目录即可运行，不需要改代码；短视频阈值、相似宽松度、「待复查」位置都能通过参数或配置文件调整；不同目录的「待复查」和报告互不覆盖
- AC-21: 在一个新的 Claude 会话里（不是开发这个工具的会话），只告诉 agent 一个新目录的路径并说"清理这个文件夹的照片"，agent 不用翻代码、不用问团队，就能完成预览、执行、还原三步；Aimee 全程不需要自己敲命令或读文档

## 交付节点

- M1: 预览版——对一个照片目录生成清理报告，标出完全重复、相似组、短视频、截图，不动任何文件。Aimee 可以先拿真实照片跑，看判得准不准。包含 AC-1 ~ AC-12
- M2: 执行版——在 M1 基础上能真正清理：删除完全重复副本、把可疑项移到「待复查」、生成操作记录并支持还原。可以用于今年这批照片的实际清理。包含 AC-13 ~ AC-19
- M3: 复用版——参数化，加上 agent 能直接读懂并调用的接口/说明（例如一个 Claude Code skill），明年 Aimee 在聊天里给个目录路径就能直接用，不用重新找团队。包含 AC-20、AC-21
